One HTTP server, two API faces. This page lists both surfaces and the behavior they share. Operation-level schemas follow the `s3vectors-2025-07-15` protocol; the repository's `conformance/` suites assert byte-level fidelity against boto3 and aws-sdk-go-v2.

## The s3vectors face {#s3vectors}

All 21 operations of the S3 Vectors protocol, named exactly as in `s3vectors-2025-07-15`:

| Area | Operations |
| --- | --- |
| Vector buckets | `CreateVectorBucket`, `GetVectorBucket`, `ListVectorBuckets`, `DeleteVectorBucket` |
| Bucket policies | `GetVectorBucketPolicy`, `PutVectorBucketPolicy`, `DeleteVectorBucketPolicy` |
| Indexes | `CreateIndex`, `GetIndex`, `ListIndexes`, `DeleteIndex` |
| Vectors and query | `PutVectors`, `GetVectors`, `DeleteVectors`, `ListVectors`, `QueryVectors` |
| Index modes | `PutVectorBucketDefaultIndexMode`, `UpdateIndexMode` |
| Tagging | `TagResource`, `UntagResource`, `ListTagsForResource` |

Requests and responses — including error shapes — are AWS byte-compatible. Point any SigV4-capable SDK at the endpoint and it behaves as if it were talking to the real service, including HTTP status codes (`400`, `404`, `409`, `402`, `429`), the `X-Amzn-Errortype` header, and `__type` in the error body. Reads are strongly consistent read-after-write. See the [emulator guide](/docs/tutorial/emulator/) for SDK examples.

> [!NOTE]
> For operation-level request and response parameters, defer to the AWS S3 Vectors API reference and to the conformance suites in the repository.

## The vectorfs face {#vectorfs}

Eight native operations under the `/x-vf/<Op>` namespace — files in, semantic search out:

| Operation | Purpose |
| --- | --- |
| `PutSource` | Ingest a source object into the file layer |
| `GetSource` | Fetch a source's record and status |
| `GetSourceData` | Fetch a source's bytes |
| `ListSources` | List sources with statuses |
| `DeleteSource` | Delete a source; GC reclaims derived vectors |
| `GetIngestStatus` | Ingest progress summary |
| `Search` | Semantic search across a bucket |
| `Reindex` | Trigger full re-embedding after pipeline changes |

Asynchronous verbs (`PutSource` async, `Reindex`) return `202` and are tracked via status polling (`GetIngestStatus`). The `vf` CLI and the MCP tools both sit on top of this face.

## Shared behavior {#shared}

- **Authentication** — SigV4 on both faces, one credential set per install (generated by `vectorfs init`). `--no-auth` accepts anything for local emulator use.
- **Error model** — identical envelope on both faces; machine-readable codes, AWS-identical on the s3vectors side.
- **Concurrency** — one writer per bucket for the file layer, enforced by TTL-heartbeat `LOCK` objects. s3vectors writes are not serialized by this mechanism.
- **Egress** — the s3vectors face makes zero outbound calls; the file layer reaches out only for model downloads or a configured embedding endpoint.

## Limits {#limits}

Structural limits — batch sizes, dimensions, metadata bounds, topK — match AWS exactly and are enforced identically. See the [limits reference](/docs/reference/limits/).
