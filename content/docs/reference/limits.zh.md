VectorFS 对 S3 Vectors 协议的结构性限额与 AWS 执行得完全一致——同样的边界、
同样的拒绝行为。QPS 限流与向量配额则**有意不**执行。

## 执行的结构性限额 {#structural}

| 操作 | 限额 |
| --- | --- |
| `PutVectors` | 每次调用 ≤ 500 个向量、≤ 20 MiB |
| `GetVectors` | 每次调用 ≤ 100 个键 |
| `DeleteVectors` | 每次调用 ≤ 500 个键 |
| 向量维度 | 1–4096 |
| 向量元数据 | 每个向量 ≤ 50 个键、≤ 40 KB |
| `QueryVectors` topK | ≤ 10,000（分页） |
| `ListVectors` 页大小 | 1–1000，默认 500 |
| 查询 segment | 1–16 |

距离度量的校验也与 AWS 一致：`cosine` 拒绝零向量，含 `NaN` 或 `Inf` 的向量
一律拒绝。

## 不执行的限额 {#not-enforced}

- **QPS / 限流** —— 不施加任何速率限制。
- **向量配额** —— 每桶、每索引的向量总量不设上限。

把这些自由当作测试期的便利，而不是生产保证。必须在真实 S3 Vectors 限流下
表现一致的环节，仍需对照真实服务验证。

## 文件层的界限 {#file-layer}

两个文件层设置约束的是摄取而非 API 调用：`max_file_size`（默认 200 MB）拒绝
过大的源；扫描间隔（默认 30 秒）决定对账器多快发现标准工具对桶的改动。
